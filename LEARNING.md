## Terminal/GitHub-README refinement pass

**What we added / changed**
Refined the terminal-window profile card (generated by `ascii_profile.py`) to
read like a real terminal + GitHub README instead of a marketing landing page:
- Progress bars: 42 → 46 segments (longer) and percentages pulled ~10px left so
  the gap to each bar shrank from ~50px to ~11px. Proportions unchanged.
- Center divider extended downward (`H - TB - 54` → `H - TB - 32`, ends ~y610)
  so it balances both columns instead of stopping mid-bar.
- Removed the blinking `█` cursor from `signoff.svg`; text is now static.
- Dropped "PROBLEM SOLVER" from the subtitle → "SYSTEM ENGINEER · BUILDER".
- Typography: swapped the font stack to prefer authentic terminal fonts
  (`'SF Mono', 'Cascadia Code', 'JetBrains Mono', Menlo, Consolas, monospace`)
  and dropped the name from bold/30px to 500-weight/26px.
- Nudged the whole right column down 16px (one wrapping `<g transform>`) so it
  centers against the taller left portrait.
- Accent color: orange `#f97316` → muted bronze `#B08D57`, defined once as the
  `GOLD` constant and used only for accents (`>`, `//`, `$`, `·`, bars, stat
  keys, EMAIL outline, cursors). All body text stays white/gray. macOS window
  dots kept their real red/yellow/green (authentic chrome, not accent).
- Bumped README image cache tag `?v=31` → `?v=32`.

**Tools / concepts involved (one line each)**
- SVG (Scalable Vector Graphics): an image drawn from shapes + text, so it stays
  crisp and can animate — the whole card is one SVG built by a Python script.
- SMIL animation: the `<animate>` tags inside the SVG that fade/draw elements in.
- GitHub `<img>` sandbox: README images render in a locked mode that blocks web
  fonts, so the card can only use fonts already installed on the viewer — hence a
  font *stack*, not a single font.
- "camo" cache: GitHub proxies README images and caches them hard, so a new
  `?v=` query string is needed to force a re-fetch after changes.

**The one-sentence why**
"I refined spacing, type weight, and swapped the accent to a muted bronze so the
card reads like an engineer's terminal, not a marketing page — without touching
the layout."

**To regenerate**
```
sips -z 120 260 avatar.png -s format bmp --out small.bmp   # only if photo changes
python3 ascii_profile.py                                   # rewrites all SVGs
```
Then commit + push (GitHub serves the SVGs from `main`), and keep the README
`?v=` bump so the change actually shows.

## Polish pass: bigger type + even vertical rhythm

**What we changed**
- Bumped every font ~12% (name 26→29, body 13→14.5, etc.) for readability.
- Removed the block-cursor next to the name — it's static now.
- **Key fix for the bottom gap:** instead of block-shifting the right column
  down, each section (name → toolchain → stats → plan → buttons) is now spaced
  individually so the column grows tall enough to fill top-to-bottom. The name
  sits high again and the buttons reach the bottom edge, level with the left bars.
- Divider extended to ~y620 and made slightly thicker/lighter (1→1.3, #2e2e2e).
- Borders more defined: toolchain box 1→1.6px (#3a3a3a), buttons 1.2→1.6px.
- Because the button font grew, its width changed, so the strip slice widths
  shifted (email 12.65%→13.67%, linkedin 36.12%→35.10%) — the README `width=`
  values had to be updated to match, or the clickable buttons misalign.
- Moved the strip `CUT` to y538, threading the black gap between the caption and
  "// right now" so the profile_top/strip seam doesn't slice through any text.

**The gotcha worth remembering**
The bottom of the card is served as one wide image (`profile_top`) stacked on
three side-by-side slices (`strip_*`). Two invariants must hold or it breaks:
(1) the strip widths as %-of-980 must equal each slice's native-width/980 (so all
slices scale to the same height and line up), and (2) `CUT` must land on a row
that is black in **both** columns (no text crossing it). Any change to button
size or the plan/bars vertical positions can violate these — re-check both.

**The one-sentence why**
"I spread the right-hand sections to fill the column instead of shoving them
down, so the layout balances top-to-bottom with no dead space under the buttons."

## TEDH intro video in the left panel + stale stats fix

**What we added / changed**
- Swapped the looping video in the card's left panel for the TEDH intro
  (`tedh-intro-dark.mp4`, kept at `~/Documents/Claude/Projects/CLEAN/out/`).
- New `banner/build_banner.sh` rebuilds `profile-video-banner.gif` in one
  command. It replaces four throwaway scripts (Swift + Python) that only lived
  in an old Codex folder and were never committed.
- 12 frames per second instead of ~6, so the fast spin/bounce doesn't stutter.
  File went from 3.5 MB to 1.9 MB anyway.
- Video panel narrowed by 16px so the centre divider shows full-height again
  (the old panel covered it, leaving a stub at the bottom).
- Video background (near-black + faint dark-red dot grid) is crushed to pure
  black so no box shows around the video.
- Repos count in the card: 27 → 15 (the real number).

**Tools / concepts involved (one line each)**
- GIF: animated image that loops silently; GitHub autoplays it, unlike .mp4.
- Headless Chrome: Chrome with no window, used to "screenshot" the SVG to PNG.
- ffmpeg: command-line video tool; here it pastes video frames onto the card
  and writes the GIF.
- Palette (palettegen/paletteuse): a GIF can only hold 256 colours, so ffmpeg
  picks the best 256 from the actual frames.
- Opaque frames: no transparent pixels, because GitHub showed them as white specks.

**The gotcha worth remembering**
The GIF bakes the whole top half of the card (name, toolchain, stats) into
every frame. The daily Action still updates `profile_top.svg`, but the README
no longer shows that file — so the stats in the GIF freeze until it's rebuilt.
That's why it said 27 repos long after it stopped being true.

**To rebuild**
```
python3 ascii_profile.py                       # only if card text/stats changed
sh banner/build_banner.sh ~/Documents/Claude/Projects/CLEAN/out/tedh-intro-dark.mp4
```
Then bump `?v=` on the GIF in README.md and push.

**The one-sentence why**
"GitHub won't autoplay video in a README, so I composite the video into the
card as a looping GIF — and I scripted it so the stats baked into it can be
refreshed with one command."
